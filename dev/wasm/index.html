Wasm backend

Same frontend as the interpreter — parse → typecheck → analysis — different codegen: the program's CPS structure is compiled explicitly into WasmGC. There is no linear memory: every wasm operand value is an anyref.

Pipeline

compileWithOps(pre) composes free functions over plain artifact records — each phase returns a fresh record with its additions, and no phase mutates an artifact it did not create. The pre argument is pipeline.ts's Prepared record (prepare's {prog, checked}): compile consumes artifacts instead of source, so gate-holding callers — wasm_host.ts's runWasm (the entrypoint gate), the CLI's ef wasm (gate + compile), the playground's run/build — prepare once and hand the same record on. Inside the pipeline, the shared fail-fast gate (frontend/pipeline.ts's rejectUnhandled) rejects residual ops neither the builtin table nor the runner's interpreter covers right away — before any codegen, the same check the interpreter's exec applies (see Interpreter). The phases:

Phase Reads Produces Job
discover Program (pre-checked by the caller) Discovery intern effect ops into the op table (returned to the host so both agree on op numbering); handler-presence pre-scan; the scope/slot/literal/split-site walk over the whole program
optimize Program Opt OPT_PASSES: treeShakeBuiltins (emit only referenced builtins) and dropDeadHostImports (live host-import set — funcref index assignment derives from it)
assignIndices Discovery, Opt Indices funcref table indices: helpers, lambdas, builtins, case fns, main; perform/handle spill slots
layoutStatics Discovery, Indices, Opt Layout static literal globals — nums, strings, bools, PI, per-handle case tables — each initialized by a GC constant expression at instantiation
emit all of the above Fn[] one local Emit context; expr() + the statement/effect emitters; order: helpers → lambdas → case fns → builtin trampolines → main (+ thunks)
buildModule all of the above bytes assemble the module incl. run + accessor init fns; in-process binaryen shrink (level 2 — matches -Oz size at ~⅓ the cost)

Each phase has its own page under this one in the sidebar.

Value representation

ef value WasmGC representation
unit ref.null any
bool i31ref 0/1
number $NUM {f64} immutable struct — one box shape per width ($F64 $F32 $I32 $U32 $I64 $U64)
string $STR — mutable i8 array, UTF-8 bytes (a string value is a bare array, no slice wrapper; strlen = array.len)
array / list $ARR slice fat pointer {(ref null $ELEMS) data, i32 off, i32 len} — immutable; views (sub) share the backing with a shifted window, only backing elements mutate
tuple $TUP {(ref null $ELEMS)} — immutable, struct-like: no offset/length, distinct from slices
closure $CLO {i31 fnIdx, (ref null $FRAME) env, i31 fsize, i31 direct flag} — immutable

Frames, variables, calls

Every call frame is a $FRAME {mut parent, mut slots} with slot array length max(fsize, argc). Closures capture their defining frame, so escaping and mutable capture work exactly like the interpreter's env chain; variables resolve statically to (frame depth, slot) — a read is struct.get $FRAME 1

  • array.get.

The call ABI is dual, over one funcref table. Classified-pure functions (empty effect row, no tail call to a suspending callee) compile to the direct signature T_DABI = (($FRAME)) -> anyref: no continuation operand, tails deliver with dret, and dcall sites invoke them directly — the $CLO's direct flag picks the entry at runtime for unknown callees (a pure-typed slot can hold a resume binder or an any-smuggled closure, which take the T_KABI arm through a synthesized land cell). A mixed function — empty row with internal handlers — keeps the direct boundary: its islands run over the ambient chain like any CPS region, the tail handler's K_HDL chains to the terminal return-cell instead of the never-set $ret, and a case fn's completion dispatches through that cell, returning the island's value from the direct entry. Builtins are trampolines (T_KABI); map/each/flatmap are compiled CPS loops that call callbacks the same way. Tail positions keep return_call/return_call_indirect (O(1) wasm stack).

Continuations and effects

Continuations are $K cells {mut kind, mut a, mut b, mut next}:

Kind a b
K_RET i31 thunk funcref index frame
K_HDL $ELEMS case table of flat [opid, fnIdx, fsize, nparams] quadruples (Return = opid −1) hframe shared by the case fns
K_SPILL frozen $FRAME snapshot unused

The mechanics of a perform:

  1. Box the args into an $ELEMS array, spill the args cell to a frame slot.
  2. Walk the continuation chain for a K_HDL whose case table contains the op.
  3. On a match, dispatch to the per-case T_KABI function over the handler's shared hframe. On no match, the effect reaches the host through ef_perform and is interpreted there (op table from compileWithOps → builtinEffectHosts), and the rest-of-site fragment continues with the resumed value.
  4. Resume as a value: the resume binder is a $CLO closure over the shared resume fn plus a per-perform-site capture record. Every call copies the captured slice afresh, re-chains the copy's bottom to a fresh HDL whose next is the k the closure was invoked with, and dispatches the resumed value through that chain — that is multi-shot resume, GC-style.

Every perform/handle site ends the inline body and reifies the code after it as a rest-of-site fragment — the compile-time split protocol.

Subset restriction: no perform/handle site inside an if branch or while body — suspension across those control-flow blocks is rejected at compile time.

Deviations vs the interpreter

Known and pinned by tests — degenerate programs only:

Deviation Note
Arithmetic on non-numbers traps (ref.cast failure) instead of producing a garbage number the checker rejects non-numeric arithmetic statically, so well-typed programs never hit it
Closures always display as [fn] interpreter may show an inferred type
Stack overflow is a wasm RuntimeError, not a JS RangeError
Heap reclamation is the host GC's job recursion depth costs only GC-reclaimed frame blocks
