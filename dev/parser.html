Parser

parseProgram(src): Program where Program = {nodes: Expr[], items: Item[], typeToks: TypeTok[]} — typeToks records every type/effect name token consumed while parsing, the LSP semantic-tokens source (VS Code extension); both backends ignore it. Recursive descent for structure, Pratt parsing for infix (precedence table below).

The flat node slice

The AST is not a tree of embedded nodes. Every expression is one element of Program.nodes; children are referenced by ExprID — a plain index into that array. Parsing x :: 41 + 1; produces:

Why flat instead of embedded:

Consumer What the ExprID buys
Type checker stamps types into side tables after the fact (nodeTypes, Checked.stamps: numKind, div, arrKind, fieldIdx, asKind) — impossible in an immutable tree
Wasm backend scopes, code labels and split sites keyed by ExprID
Closures a closure carries its own nodes slice, so it stays valid across REPL lines and separate programs
Walks exprChildren(id, nodes) gives uniform traversal for every pass (checker, analysis, lint, wasm)

Grammar strategy

Construct Strategy
Binary operators Pratt loop over the PREC table, left-associative
Unary - / ! desugar to calls: -e → app(sym neg, [e]), !e → app(sym not, [e]) — the checker sees ordinary calls of builtins named neg/not
&& / || desugar to if — short-circuit falls out for free
Calls, field access postfix loop: f(a)(b).x.0 parses as successive accesses
Everything else recursive descent

Node kinds

Variant Source Notes
num 1, 1.5 isFloat decides the untyped int/float num type; checker stamps numKind with the resolved width
str · bool · unit literals escapes decoded here (parseStr)
sym names variable references and desugared operator names
lambda fn (p) { … } optional : R / ! { Effs } annotations; the width-ambiguity bookkeeping for unannotated params lives in stamps.ts's lamWidths map, not on the node
let x := e; x :: e; x: T = e; mut distinguishes := from ::
dlet [a, b] := e; destructuring bind with optional per-field annotations
assign x = e; mutation of an existing mutable binding
if · while · block control flow &&/|| desugar into if
perform Op!(args) name + arg nodes
handle handle { … } case … body + HandlerCase[] (op, params, resume, resumePos, body)
app f(x) checker stamps div/numKind on operator applications
as @as(e, T) checker stamps asKind (trunc vs boolnum) into Checked.stamps
arr [a, b, c] array if homogeneous, tuple if heterogeneous — decided by the checker (arrKind in Checked.stamps)
field e.x / e.0 checker resolves the field index into Checked.stamps (fieldIdx)

Items

Item Source Notes
{e} expression statement the program's value is the last one
{effect, sig} Op :: effect(p): ret; the only way Op! becomes legal (see Type checker)
{alias} type Pair(a, b) = [a, b]; parametric type alias

Aliases and parser-allocated type variables

Aliases are registered top-down as type items are parsed; a typeParamStack lets an alias body reference its own parameters as type variables (type Pair(a, b) = [a, b]).

Type variables allocated by the parser (alias parameters, and arguments omitted from a parametric alias use) live in a negative id space, so they never collide with a checker Unifier's ids — the unifier treats unknown ids as their own root, so such variables behave as ordinary unbound variables. Alias instantiation (instantiateAlias) is pure substitution — no unifier involved. Recursive aliases are not supported (a recursive alias would stack-loop the substitution).

Errors

Parsing throws Error with messages like Expected ";", got "}" — token positions come from the lexer, so later phases can attach real line/col information.
